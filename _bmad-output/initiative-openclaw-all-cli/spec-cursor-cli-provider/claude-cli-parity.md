# claude-cli parity

What OpenClaw's built-in `claude-cli` backend does (OpenClaw 2026.10.3, `extensions/anthropic/setup-api.js`), and the target for each provider. Spike results: `../spike-cursor-transport/spike-cursor-transport.md`. Status: **match** (same behavior), **approx** (same outcome, different mechanism), **gap** (not possible; reason given), **spike** (unknown until tested), **tbd** (not researched).

| # | claude-cli feature | Mechanism in claude-cli | cursor-cli | Antigravity |
|---|---|---|---|---|
| P1 | Provider in `/model`, model aliases | `modelProvider`, `modelAliases`, `resolveModelId` | approx: `/model` and `openclaw models list` show the account's models as `cursor-cli/<name>`, from a throwaway ACP `session/new` (its `models` state; no turn, no tokens), reused for one minute and dropped when the environment changes; the name is the base ID without Cursor's parameter list (`grok-4.7[context=256k,...]` is `grok-4.7`), unique and mapped by the adapter to the exact ID, which is checked against the session's own list at every turn (`model_not_found` for a model the account lacks); `modelAliases` carries only Cursor's spellings of Auto; a failed listing leaves `cursor-cli/auto` alone and logs. Live: `test/live/model-catalog.live.test.ts` | tbd |
| P2 | Subscription login counts as auth | `syntheticAuthRefs`, `subscriptionAuthDispatch` | match: synthetic auth from `cursor-agent status` (live: `Logged in as <email>`; the logged-out wording is unconfirmed) or `CURSOR_API_KEY`; the catalog rows are available with either and `available: false, missing-auth` without. Live: `test/live/model-catalog.live.test.ts` | tbd |
| P3 | Streaming text, thinking, tool progress | `output: jsonl`, Claude stream-json | approx: text and thinking deltas over ACP (`agent_message_chunk`, `agent_thought_chunk`) as they arrive; Cursor's `tool_call`/`tool_call_update` map to display-only `toolStart`/`toolResult` (one pair per call ID, open calls closed as aborted at turn end), named in OpenClaw's tool names, proxied OpenClaw tools as `mcp__openclaw__<tool>`; the host does not track them as tool execution, unlike claude-cli's stream events (live: 159 text and 4 thinking deltas, first one 9.6 s before the result; a real OpenClaw run counted one `read` and one proxied `session_status` call; `test/live/streaming.live.test.ts`) | tbd |
| P4 | Warm process per conversation | `liveSession: "claude-stdio"` via custom `execute` | approx: the core keeps one `agent acp` process per conversation (spiked: later turns 2.4–2.6 s vs 5–11 s first), but OpenClaw 2026.10.3 puts the per-turn MCP settings path into its live-session fingerprint, so it restarts the process every turn and the next turn resumes with `session/load`. A process is reused only when model, mode, cwd, home, auth profile, and session ID all match (AD-13), and one chat never has two processes; live test `test/live/session-resume.live.test.ts` (2026-10-18) | tbd |
| P5 | Resume a session | `sessionArgs`, `resumeArgs`, `--resume` | match: ACP `session/load` from `ctx.sessionId` when `useResume`; the session ID the CLI ends up with is emitted every turn; `/reset` passes no ID and starts a new session; a chat the home lacks (another agent's, deleted) fails `session_expired` (text `CLI session not found`), never a silent fresh chat, and `freshSessionRecovery: "invalidated-only"` leaves a fresh retry with reseeded history to the host; live test `test/live/session-resume.live.test.ts` (2026-10-18) | tbd |
| P6 | Fork, resume at a checkpoint | `forkArg`, `resumeAtArg` | gap: no fork or checkpoint flag in cursor-agent | tbd |
| P7 | OpenClaw tools as MCP | `bundleMcp`, `claude-config-file` | match: the plugin hands Cursor one MCP proxy per live session, and nothing else, in ACP `mcpServers` (new and load); it forwards to each turn's loopback URL and headers from `GEMINI_CLI_SYSTEM_SETTINGS_PATH` and rejects calls between turns; live test `test/live/mcp-proxy.live.test.ts`, and a real OpenClaw run called `agents_list` and `session_status` through it; `-p` needs `.cursor/mcp.json` at the user's git root | tbd |
| P8 | Native shell replaced by OpenClaw `exec`/`process` | `hostOwnedTools`, `nativeToolMode: "selectable"` | approx: the per-agent `cli-config.json` denies `Shell(*)`, `Write(**)`, and `WebFetch(*)`, so the native shell does not run; a shell request that still arises (a home that leaves shell to ask) goes to `ctx.requestToolPermission`, and after a denial the model falls back to OpenClaw `exec` when the run serves it (live, stub host: `test/live/permission-routing.live.test.ts`). OpenClaw 2026.10.3 serves no `exec` to a `prepare-execution` backend (`hostOwnedTools` applies only to `execution-args`), so a real run has no `exec` tool | tbd |
| P9 | Tool approvals through OpenClaw | permission hook to `before_tool_call` / exec approval | approx: permission requests (shell, MCP, web fetch and search, reads) go to `ctx.requestToolPermission`, canonical `toolName`/`toolInput` from the adapter; `allow` selects `allow_once`, deny, error, a changed input, or no matching option rejects or cancels; abort and late requests answer `cancelled`. Native edits cannot ask (probed, cursor-agent 2026.10.16: agent mode applies them without a request, whatever the permissions and `approvalMode`; `ask` and `plan` mode have no edit tool), so they stay denied by `Write(**)` and `ask` mode, never host-approved | tbd |
| P10 | Tool policy (`tools.allow`/`deny`) enforced | `toolAvailabilityEnforcement: "execution-args"` | approx: `nativeToolMode: "selectable"` with `toolAvailabilityEnforcement: "prepare-execution"`; the host filters the OpenClaw tool list (live: `tools.deny` hides a tool from the model) and the adapter translates nothing (AD-9). `prepareExecution` confirms a run's native selection (`toolAvailabilityEnforced`) only if it keeps native `read`, `grep`, and `glob`, which Cursor cannot switch off per turn; a run that selects none (OpenClaw 2026.10.3 always sends `native: []` for caps, `disableTools`, and system agents) is refused with a message. A native tool outside the selection is denied without asking the host | tbd |
| P11 | Skills as a native plugin | temporary plugin via `--plugin-dir` | spike: `cursor-agent --plugin-dir`; fallback: prompt catalog | tbd |
| P12 | System prompt every turn | `--append-system-prompt-file`, `systemPromptWhen: "always"` | spike: no system-prompt flag known; prompt prefix or ACP | tbd |
| P13 | Images | `imageArg: "@"`, workspace scope | spike | tbd |
| P14 | Native and manual compaction | `ownsNativeCompaction`, `/compact` | spike | tbd |
| P15 | History reseed and fallback prelude | `reseedFromRawTranscriptWhenUncompacted`, prelude from Claude JSONL | approx: reseed with a Cursor API-key profile; prelude from Cursor transcripts: spike | tbd |
| P16 | Usage per turn | parsed from the terminal event | `-p`: match (`result.usage`); ACP: gap (no usage in `session/prompt`, no `usage_update`; input side estimable from the session store within about 2%, output not; see the spike write-up) | tbd |
| P17 | Clean env, watchdog, timeouts | `clearEnv`, `reliability.watchdog` | match: `clearEnv` is declared (and applied to the listing and auth probe); the host's watchdogs abort `ctx.abortSignal` and the backend declares no `reliability`, like `claude-cli`; plus a per-backend turn and process cap, pid locks with orphan reaping, and close-all on unload Live test: `test/live/operations.live.test.ts` | tbd |
| P18 | Side questions without tools | `sideQuestionToolMode: "disabled"` | approx: `executionMode: "side-question"` opens a throwaway `ask`-mode session with no MCP server, no resume, every permission request rejected, and no session ID reported; `sideQuestionToolMode: "disabled"` is set, but Cursor cannot switch off native `read`, `grep`, `glob` per run, so the model may still read files (no shell, no write, no OpenClaw tool); live test `test/live/session-resume.live.test.ts` (2026-10-18) | tbd |
| P19 | Binary detection, live tests | `runtimeArtifact`, `liveTest` | approx: OpenClaw finds `cursor-agent` on `PATH`; the plugin enforces the minimum version 2026.07.06 with its own `--version` check; `runtimeArtifact` cannot describe Cursor's bash launcher install, so it is not declared Live test: `test/live/operations.live.test.ts` | tbd |
