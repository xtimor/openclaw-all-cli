# claude-cli parity

What OpenClaw's built-in `claude-cli` backend does (OpenClaw 2026.10.3, `extensions/anthropic/setup-api.js`), and the target for each provider. Spike results: `../spike-cursor-transport/spike-cursor-transport.md`. Status: **match** (same behavior), **approx** (same outcome, different mechanism), **gap** (not possible; reason given), **spike** (unknown until tested), **tbd** (not researched).

| # | claude-cli feature | Mechanism in claude-cli | cursor-cli | Antigravity |
|---|---|---|---|---|
| P1 | Provider in `/model`, model aliases | `modelProvider`, `modelAliases`, `resolveModelId` | approx: `/model` and `openclaw models list` show the account's models as `cursor-cli/<name>`, from a throwaway ACP `session/new` (its `models` state; no turn, no tokens), reused for one minute and dropped when the environment changes; the name is the base ID without Cursor's parameter list (`grok-4.7[context=256k,...]` is `grok-4.7`), unique and mapped by the adapter to the exact ID, which is checked against the session's own list at every turn (`model_not_found` for a model the account lacks); `modelAliases` carries only Cursor's spellings of Auto; a failed listing leaves `cursor-cli/auto` alone and logs. Live: `test/live/model-catalog.live.test.ts` | tbd |

| P7 | OpenClaw tools as MCP | `bundleMcp`, `claude-config-file` | match: the plugin hands Cursor one MCP proxy per live session, and nothing else, in ACP `mcpServers` (new and load); it forwards to each turn's loopback URL and headers from `GEMINI_CLI_SYSTEM_SETTINGS_PATH` and rejects calls between turns; live test `test/live/mcp-proxy.live.test.ts`, and a real OpenClaw run called `agents_list` and `session_status` through it; `-p` needs `.cursor/mcp.json` at the user's git root. | P8 | Native shell replaced by OpenClaw `exec`/`process` | `hostOwnedTools`, `nativeToolMode: "selectable"` | approx: the per-agent `cli-config.json` denies `Shell(*)`, `Write(**)`, and `WebFetch(*)`; the last has no effect (a native web fetch asks the host in either mode and OpenClaw's policy decides). When `exec` is in the host's tool list for the turn (read by the plugin, after all tool policy), the turn runs in Cursor's `agent` mode, where the native shell, write, edit, and delete are blocked without asking (live, 2026-10-19); otherwise in `ask` mode. The backend declares `toolAvailabilityEnforcement: "execution-args"` with `resolveExecutionArgs` and `hostOwnedTools: ["exec", "process"]` (P7, P8, P10 all decided), as `claude-cli` does, so OpenClaw 2026.10.3 serves its own `exec` and `process` over its MCP loopback and the proxy forwards them: approvals, sandbox, timeout, output cap are OpenClaw's and the plugin runs and parses no command (live: `test/live/exec-tool.live.test.ts`). Abort: the plugin closes the call and OpenClaw kills the command's processes (live, within 10 s). A native shell request gets "Use OpenClaw exec" from the host only in a run that serves exec; elsewhere `Shell(*)` alone blocks it. Gaps: with exec host `node`, or a rooted run, the host serves no `exec`, and a capped run (`native: []`) is refused (`claude-cli` falls back to native Bash); Cursor's MCP client gives up on a call after 60 s without hanging up, so the proxy stops a `tools/call` at 55 s (the host then kills the command) and tells the model to use the background; commands can read the Gateway environment (the key can be given to the Cursor process only through the plugin config `env`) and write the agent home; a sandboxed agent's native reads see the host workspace | tbd |
| P9 | Tool approvals through OpenClaw | permission hook to `before_tool_call` / exec approval | approx: permission requests (shell, MCP, web fetch and search, reads) go to `ctx.requestToolPermission`, canonical `toolName`/`toolInput` from the adapter; `allow` selects `allow_once`, deny, error, a changed input, or no matching option rejects or cancels; abort and late requests answer `cancelled`. Native edits cannot ask (probed, cursor-agent 2026.10.16: agent mode applies them without a request, whatever the permissions and `approvalMode`; `ask` and `plan` mode have no edit tool), so they stay denied by `Write(**)` (agent mode applies them unless it denies them; `ask` mode, used for side questions, has no edit tool), never host-approved. The model's commands go through OpenClaw `exec`, whose approvals (`tools.exec.ask`, `exec.approval.*`) are OpenClaw's (live: `test/live/exec-tool.live.test.ts`) | tbd |
| P10 | Tool policy (`tools.allow`/`deny`) enforced | `toolAvailabilityEnforcement: "execution-args"` | approx: `nativeToolMode: "selectable"` with `toolAvailabilityEnforcement: "execution-args"`, as `claude-cli`. `resolveExecutionArgs` returns the host's `baseArgs` unchanged, or nothing when the run's native selection drops a tool Cursor cannot switch off (the host then fails the run); `prepareExecution` refuses the same selection early with a message. The host filters the OpenClaw tool list (live: `tools.deny` hides `exec`/`process` and nothing runs) and the adapter translates nothing (AD-9). A run that selects no native tools (OpenClaw 2026.10.3 always sends `native: []` for caps, `disableTools`, and system agents) is refused. A native tool outside the selection is denied without asking the host | tbd |

| P12 | System prompt every turn | `--append-system-prompt-file`, `systemPromptWhen: "always"` | approx: no ACP or CLI system-prompt channel (`session/new` takes `cwd` and `mcpServers` only; `cursor-agent`'s hidden `--system-prompt` is team-only and not read by `acp`), so the core sends `ctx.systemPrompt` as a marked block at the start of the prompt on a chat's first turn and again whenever it changes (a hash per native chat, kept in `system-prompt-delivered.json` in the agent home, so a restart or `--local` run does not resend; the change check masks the date and the runtime line's model, channel, capabilities, and active-node fields, and a change of only those sends a one-line runtime update with the current values instead of the block; the true block comes first, and the plugin neutralizes its own marker spellings in the text it forwards, while text that reaches Cursor by other routes, such as tool output or Cursor's native read, is not neutralized); the backend declares `systemPromptWhen: "always"` with a marker `systemPromptArg` that the host never passes to a plugin-owned execute, so a changed tool list or extra system prompt keeps the chat (`reuse=reusable-drift`); declaring it also turns on the host's workspace bootstrap routing for this backend (a first-run `BOOTSTRAP.md` may leave the system context); the block lives in Cursor's chat, not OpenClaw's transcript, and Cursor's own summarization may shorten it; live test `test/live/skills-system-prompt.live.test.ts` | tbd |
| P13 | Images | `imageArg: "@"`, workspace scope | approx: the host writes each image to its private cache (`<OpenClaw temp>/openclaw-cli-images`, swept after 7 days; the host itself caps an image at about 6 MiB) and appends the paths to the prompt; the core takes that trailing block off only when every line has the host's exact path shape (`openclaw` or `openclaw-<uid>` directly under `/tmp` or the temp dir) and every file was written within 2 minutes before the turn, so a path typed by a user or channel for an older file stays text; it then reads each file (regular, one link, owned by the Gateway's user, in a directory that user owns and others cannot write, ≤10 MiB, ≤10 images, ≤20 MiB total, png/jpeg/gif/webp/bmp by magic bytes) and sends ACP image blocks after the text; an image it cannot send becomes a one-line note that asks the model to tell the user; nothing is written; without a process uid (Windows) the prompt is left as it is; catalog rows declare image input; Cursor keeps earlier images in its chat (no resend); requires promptCapabilities.image, so a CLI that lacks it fails every turn, text-only ones too, with capability_mismatch; live test test/live/images-compaction.live.test.ts | tbd |
