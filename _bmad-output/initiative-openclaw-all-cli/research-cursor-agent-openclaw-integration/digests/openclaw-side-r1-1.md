## Answers

1. **Plugin API.** Register a CLI backend with `api.registerCliBackend(...)` inside `definePluginEntry` (from `openclaw/plugin-sdk/plugin-entry`). Declare the id in `openclaw.plugin.json` `cliBackends` (and optionally `setup.cliBackends`), and point `package.json` `openclaw.extensions` at the entry (claims 2, 3, 5, 6). Since 2026.2.22, mechanics moved out of `agents.defaults.cliBackends` config into plugin code; selection is by `<id>/<model>` prefix or per-model `agentRuntime.id`, and install is via `openclaw plugins install` (claims 4, 12, 33). The heavier alternative is the experimental agent-harness API (claim 32).
2. **How `claude-cli` works.** Claude Code runs in `-p --output-format stream-json` mode with the prompt on stdin, the system prompt appended via file, `--session-id`/`--resume`, `--fork-session`, `modelArg --model` with aliases, and `serialize: true`. It uses a warm stdio subprocess per conversation, a 48h turn timeout plus a no-output watchdog, and per-conversation queue keys (claims 8, 9, 25, 29). Gemini uses `stream-json` + `--resume`, and `codex-cli` no longer exists upstream (claims 10, 11).
3. **Tools, MCP and skills in CLI mode.** OpenClaw does not inject tool calls into the CLI protocol. Instead, the backend opts into `bundleMcp`, a per-run, grant-authenticated loopback MCP server exposing Gateway tools, which the CLI calls as its own MCP tools (`mcp__openclaw__*` for Claude) (claims 13, 14). The CLI's native tools still execute inside the CLI under OpenClaw permission hooks, and skills are passed as a Claude plugin dir or a prompt catalog (claims 15, 16). So OpenClaw owns policy and the transcript, but the CLI drives the tool loop. Local 2026.2.22 had tools fully disabled (claim 17).
4. **History.** Only the new message plus bounded session notes are sent; continuity comes from CLI-side resume, with one binding per backend (claims 18, 21). A fresh session can reseed from OpenClaw history, but only under a matching account boundary, and opaque native CLI logins are refused automatic replay. Cross-backend switches otherwise get only a metadata note and `sessions_history`; there is a fallback chain, and a prelude exists only from `claude-cli` (claims 19, 20, 22, 28).
5. **Usage and streaming.** Usage parsed from the CLI's terminal events is persisted on the assistant transcript entry and passed to `llm_output` hooks (claim 23). Streaming is backend-specific: JSONL parsers emit incremental text and thinking, while text/json backends buffer until exit (claims 7, 24).
6. **Known issues.** #116235 is open: Gateway restarts strand loopback MCP on live runs (claim 30). Many session-churn and binding bugs were fixed between 2026-04 and 2026-10 (claim 31). From the source: a non-Claude backend with `serialize: true` serializes globally across all agents, while live sessions are keyed per agent+conversation. Per-agent CLI home isolation is not provided by core (claims 25, 26, 27).

## Leads

- **Global serialization for non-Claude backends** (claim 25). A `cursor-cli` plugin must choose between `serialize: false` (fully concurrent, no per-session ordering) and `serialize: true` (all agents on one global lane), unless it uses `liveSession` (only `claude-stdio` is documented). Check whether a third-party plugin can declare `liveSession` or a custom `execute` transport to get per-owner queue keys.
- **Account boundary vs. opaque `cursor-agent` login** (claim 19). Automatic history reseed (goal b) may be refused unless the plugin forwards a static credential (for example a Cursor API key through an OpenClaw auth profile). Verify how `defaultAuthProfileId`/`authEpochMode` interact with this boundary.
- **Which `bundleMcpMode` fits `cursor-agent`** (claims 13, 14): `claude-config-file` (`--mcp-config`-style), `gemini-system-settings`, or none. Does cursor-agent accept a per-run MCP config file or env-scoped config dir, and can its native tools be disabled per run (`nativeToolMode: "selectable"`)?
- **Per-agent CLI home** (claim 27): can `prepareExecution` set a per-agent `HOME`/config dir env for cursor-agent (the equivalent of `CLAUDE_CONFIG_DIR`)? Also check whether two agents sharing one workspace dir collide in cursor-agent's own chat store.
- **Contradiction between the claude-cli docs and #79047**: #79047 says cross-backend context is not preserved, while the current docs describe metadata notes, reseed and a fallback prelude. Check the CHANGELOG for when cross-backend reseed landed and whether it covers third-party backends.
- **Harness vs. CLI backend**: decide whether `cursor-cli` should be a CLI backend (stable, documented for third parties) or an agent harness (richer native events and usage, but experimental) (claim 32).
- **`openclaw/plugin-sdk` package exports for `CliBackendPlugin` types** (`src/plugins/cli-backend.types.ts`): read it for the exact `parseJsonlEvent` return union and the `execute` transport signature.
- **Model discovery for `/model` pickers**: how a CLI backend plugin lists available models (`setup.cliBackends` descriptors, model catalog).
