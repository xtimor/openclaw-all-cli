## Hypothesis verdicts

- **H1 — mostly confirmed, with corrections.** The config-dir formula is confirmed (claim 1). Chats are at `<configDir>/chats/<md5(resolve(cwd))>/<uuid agentId>/store.db` (claim 3). `CURSOR_DATA_DIR` defaults to `~/.cursor` and holds `projects/` and `ts/<slug>.json` (claim 4). The `proper-lockfile` spawn lock and `ts.lock` are confirmed for a shared helper (claim 5), but the helper appears to be telemetry-related ("telem-manager"), and I did not resolve the directory of `ts.lock`.
- **H2 — confirmed for 04.17.** The macOS Keychain is the only store on darwin (claim 9). `AGENT_CLI_CREDENTIAL_STORE` is missing from 04.17, so it requires ≥ v2026.06.29 (claim 13). The darwin auth file path is hardcoded to `homedir()/.cursor/auth.json` in 04.17 (claim 12). For newer versions, the path is unverified.
- **H3 — partly confirmed.** The user `mcp.json` is hardcoded to `~/.cursor/mcp.json`, and the project file is `<projectRoot>/.cursor/mcp.json` (claim 6). Global servers are auto-approved (claim 22). I did not verify `--approve-mcps` this run.
- **H4 — confirmed, with additions.** The token set and deny precedence are confirmed (claim 16), and `Read` is deniable. Beyond those tokens there are three gates: `approvalMode` (claim 15), Delete with no token (claim 19), and `autoAcceptWebSearch` (claim 24). I found no documented flag or setting that removes a built-in tool from the model's tool set.
- **H5 — refuted as config.** These are shell-integration and terminal-capture variables, not state controls (claim 14).

## Answers

1. **Which paths follow `CURSOR_CONFIG_DIR`.** These follow the config dir: `cli-config.json`, `chats/`, and `acp-sessions/`. These do not: user `mcp.json` (hardcoded to `~/.cursor`), worktrees (`CURSOR_WORKTREES_ROOT` or `~/.cursor/worktrees`), and darwin `prompt_history.json`. `projects/` and `ts/` follow `CURSOR_DATA_DIR`. So per-agent `CURSOR_CONFIG_DIR` + `CURSOR_DATA_DIR` isolates chats, CLI config, and project data. User-level MCP config stays shared, so per-agent MCP must go in the project `.cursor/mcp.json` of each agent's cwd (claims 1–8).
2. **Auth sharing.** Yes. In 04.17 on macOS, a fresh `CURSOR_CONFIG_DIR` still finds the shared login: the Keychain is keyed only by account `cursor-user` and services `cursor-*-token`, and does not depend on the config dir. A Keychain item exists locally (claims 9–10). On ≥ v2026.06.29, `AGENT_CLI_CREDENTIAL_STORE=file` would switch to a file whose location is not documented (claim 13). `CURSOR_API_KEY` takes a personal "user API key" from Dashboard → API Keys (claim 27), so it is tied to the user's account. I found no Cursor doc saying how CLI requests made with a user API key are billed against a subscription. The BYOK help pages found concern provider keys, which are a different thing. Unverified belief: the user key draws on the same account plan as browser login.
3. **Headless permissions.** In `-p` without `--force`, an operation that needs approval is denied without a prompt, so the run does not block. The agent sees the failure (claims 17–19). Per the forum and docs, file edits are "proposed, not applied". `Read` is deniable (claim 16). No source explicitly confirms that `deny: ["Shell(*)", "Write(**)"]` blocks all shell and edit calls; it is consistent with glob support and deny precedence, but untested. Delete has no token and stays rejected in `-p` unless `--force` or `unrestricted` is used, which in this case is the desired outcome. I found no documented "deny all non-MCP tools" switch. The closest combination is `-p` without `--force`, plus `approvalMode: "allowlist"`, plus deny `Shell(*)`, `Write(**)`, `Read(**)`, `WebFetch(*)`, plus allow `Mcp(<server>:*)`. The tools would remain in the model's tool list and fail when called.
4. **Concurrency.** Running several CLI processes at once is a supported scenario. v2026.07.06 fixed `cli-config.json` corruption from concurrent processes, so 04.17 is affected (claim 21). A shared helper is spawned under a lockfile, and clients register with it (claim 5). I found no evidence about two processes resuming the same chat or about locking on `store.db`.
5. **Newer version.** None is installed; only `2026.04.17-787b533` exists, and both `~/.local/bin/agent` and `cursor-agent` link to it. The changelog lists releases up to v2026.10.08, so an upgrade is needed for `AGENT_CLI_CREDENTIAL_STORE`, the `cli-config.json` concurrency fix, `approvalMode`, and `autoAcceptWebSearch`.
