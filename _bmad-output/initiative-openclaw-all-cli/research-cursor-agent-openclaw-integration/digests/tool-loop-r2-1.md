# Tool loop, round 2: Cursor surfaces for a host-owned tool loop

Scope: which Cursor surfaces let OpenClaw own the tool loop, or at least inject tools per session. All sources accessed 2026-10-15. Repos were cloned with `--depth 1` into `/tmp/recon-*` on that date. `@cursor/sdk@1.0.37` was unpacked from npm.

## Answers

1. **ACP.** Cursor's docs only document `.cursor/mcp.json` MCP, even though the ACP spec makes `session/new.mcpServers` the standard way for a client to inject its own tools (claims 2, 3). Whether cursor-agent honors client `mcpServers` is unverified. Permission handling is per call (`reject-once`; no reject-always), and whether the model continues after a rejection was not found. ACP usage reporting is undocumented. `session/load` is documented. So ACP gives at best a "reject built-ins and supply an MCP server" loop, which still needs a live test.
2. **`@cursor/sdk` (local)** is the only official surface that meets the requirement in documented terms. `tools: []` (or `tools: ["mcp"]`) removes the built-ins, while `local.customTools` or inline `mcpServers` inject host tools per run, and `execute` runs in the caller's process (claims 8–10). The SDK still runs the loop internally, so a plugin has to bridge each `execute` call to OpenClaw's tool runner while the run stays open. The plugin cannot return the tool call from a model step and end the turn. Auth is API-key based: a browser login mints a 90-day user key that bills against the same account pools (claims 11, 12). It does not reuse the `agent login` session.
3. **oakimov** gives a true host-owned loop by speaking Cursor's private `agent.v1.AgentService/Run` protocol. It advertises host tools as a synthetic MCP server and holds the Run open while the host executes them (claims 16, 17). The cost is ToS and protocol-drift risk, which the author states openly; usage is estimated, and the field layout is pinned to a CLI build (claims 18, 19).
4. **Nomadcxx and chiarelli** use the official CLI or SDK and hijack the loop by intercepting `tool_call` events and cancelling the run before Cursor executes them (claim 20). chiarelli adds `cli.json` deny rules so cursor-agent cannot write, run shells or use MCP (claim 23). Neither uses SDK `customTools` or `tools: []`.
5. **BDK** is a Cursor server and runtime with HTTP and Slack channels and a rich event stream. `actions.requested` reports tools the runtime executes (claim 15, inference). No host-defined remote tool return path was found, and its relationship to the CLI or SDK is unclear.
