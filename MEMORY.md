## Decisions (user)

- Goal: `claude-cli` experience and features for every CLI; Cursor first, Antigravity next.
- The agent decides design; the user decides strategy only.
- Work only against the isolated OpenClaw; the user's own Node and OpenClaw (`~/.openclaw`, 2026.2.22) are upgraded at the end (epic entry 18).
- A host without a Cursor login still develops. It installs Node 24 and OpenClaw 2026.10.3 into `.spike` when they are missing. The live `cursor-agent` check waits for a machine that has the login, and that wait is not a question (user, 2026-10-16).
- Cursor API key optional. No public release in this initiative.
- Cursor usage must be found; shipping without it is a last resort.

## Facts learned the hard way

- `cursor-agent -p` reads project `.cursor/mcp.json` only at the workspace's git root, and ignores project `.cursor/cli.json` permissions; permissions work from `CURSOR_CONFIG_DIR/cli-config.json`.
- `cursor-agent acp` honors `session/new.mcpServers` (HTTP + headers), asks permission for shell, auto-applies edits unless `Write(**)` is denied, and reports no usage.
- `deny: Read(**)` does not block grep/glob.
- OpenClaw mints a new loopback MCP token per run; a warm session needs the per-turn MCP proxy (AD-12).
- OpenClaw owns session binding (`ctx.sessionId`/`useResume`) and per-session lanes with `liveSession`; do not duplicate them.
- Sandboxed shells can't read the Cursor login from the Keychain; run `cursor-agent` with full permissions.
- OpenClaw scans a plugin's whole root dir. A `--link` install of the checkout fails (`.spike/` holds hundreds of nested packages; state under the root trips "directory changed during admission"). Install a packed `.tgz` (`npm run dev:install`); copy install needs built `dist/` (`openclaw.runtimeExtensions`).
- Manifest `providers: ["<backend>"]` is required for `providerCatalogEntry` (synthetic auth) to load; `cliBackends` alone leaves `models status` at `[indeterminate]`. Entry may export an array.
- A CLI backend's `execute` yields records; OpenClaw JSON-stringifies them into `parseJsonlEvent`. Records with `type: "result"` end the turn. `useResume` needs non-empty `resumeArgs`; `sessionMode: "existing"` passes only the stored ID.
- Vitest env makes OpenClaw mute output; strip `VITEST*` when a test spawns it.
- Host-less checks use `test/fixtures/fake-cursor-agent.mjs` (ACP stand-in; steer with `[[hang]]`, `[[crash]]`, `[[ask-permission]]`, `[[refuse]]`, `[[ask-json]]<json>` (`{toolCall, announce?, options?}`: an ACP permission request; `announce` is sent first as a `tool_call` update), `say:<text>`; env knobs `FAKE_CURSOR_DEFAULT_MODEL` (an exact model id, default `default[]`), `FAKE_CURSOR_MODEL_SURFACE` (`both`, `state`, `options`), `FAKE_CURSOR_NO_MODELS`, `FAKE_CURSOR_IGNORE_CANCEL`, `FAKE_CURSOR_IGNORE_TERM`, `FAKE_CURSOR_IGNORE_STDIN_EOF`, `FAKE_CURSOR_NO_INIT`, `FAKE_CURSOR_NO_ASK_MODE`, `FAKE_CURSOR_LOGGED_IN`, `FAKE_CURSOR_LOG` (lines carry `t`, epoch ms), `FAKE_CURSOR_LOG_END` (also log `prompt/end`), `FAKE_CURSOR_CAPS` (JSON shallow-merged into `initialize`'s `agentCapabilities`; the default is the real report), `FAKE_CURSOR_AUTH_METHODS` (JSON that replaces `authMethods`), `FAKE_CURSOR_VERSION`, `FAKE_CURSOR_VERSION_EXIT`; prompt `[[sleep:<ms>]]`). It proves wiring only, not Cursor behavior.
- Plugin startup loading (#148584, OpenClaw 2026.10.3): with no config naming `cursor-cli`, the Gateway loads the plugin on the first turn selecting it; with `agents.defaults.model.primary = cursor-cli/auto` it loads at startup.

- Live Cursor (2026.10.16): with `CURSOR_API_KEY`, skip `authenticate{cursor_login}` (it opens a browser and fails). ACP lists models under `models` with ids like `default[]`, and also in a `configOptions` model select with the same ids (see Model catalog). Cursor returns backend errors as message text with `end_turn`. The proxy must allow `agentn.global.api5.cursor.sh` for a real turn.
- Per-agent home (entry 2): `<agentDir>/openclaw-all-cli/<backendId>/` with `cli-config.json` permissions; real `cursor-agent acp` in agent mode creates no file with it and does create one without it (checked 2026-10-17, `test/live/per-agent-home.live.test.ts`). Unverified: a login kept in the config dir (no Keychain) may be invisible to a per-agent `CURSOR_CONFIG_DIR`; this host has only `CURSOR_API_KEY`.
- MCP proxy (entry 3, 2026-10-17): Cursor connects to its MCP servers while `session/new`/`session/load` runs and drops a server for good after one rejected connection. So `execute` registers and activates the host live-session handle, and points the proxy at the turn's target, before `adapter.open`. Otherwise the host answers 401 (its MCP grant capture is not active yet).
- Host settings file (`GEMINI_CLI_SYSTEM_SETTINGS_PATH` in `ctx.env`, real OpenClaw 2026.10.3): `{mcp:{allowed:["openclaw"]},mcpServers:{openclaw:{url:"http://127.0.0.1:<port>/mcp",type:"http",headers:{Authorization:"Bearer <64 hex>","x-openclaw-cli-capture-key":"<uuid>"}}}}`. The path is a new temp file per attempt, so the host's live-session fingerprint (which hashes env values) differs every turn: no warm reuse, every turn restarts the process and resumes with `session/load`. The URL is stable per Gateway; token and capture key change per turn.
- Open risk: if a host version makes the fingerprint stable, `live.activate` moves the later turn's grant onto the first turn's bearer and capture key (`adoptProcessToken`, `beginCapture(record.capture.key)`), and the later turn's file credentials would be rejected with 401. AD-12 reads each turn's file; check this before lifting the restart.
- Live tests share one isolated OpenClaw state: `vitest.config.ts` runs live files serially. Two `openclaw agent --local` at once fail.
- Gateway for multi-turn checks: `scripts/dev-openclaw.sh run gateway run --allow-unconfigured --auth none --port 18911`, then `OPENCLAW_GATEWAY_PORT=18911 ... run agent --session-id X` (no `--local`). Do not `pkill -f` by name from a shell whose command line contains it.
- Review fixes (2026-10-17): a first turn with no usable settings leaves the process degraded (Cursor drops the server after the proxy's 503), so `reusable()` skips it. `handle.close()` during `adapter.open` is detected after the open and the new session is closed. The proxy drops the CLI's `x-openclaw-*`, `cookie`, `origin`, `x-forwarded-*` headers. `ExecuteOptions.mcp` (from manifest P7) off means no proxy, no `mcpServers`, no warning.
- Permission routing (entry 4, 2026-10-17, cursor-agent 2026.10.16 / OpenClaw 2026.10.3):
  - ACP `session/request_permission` carries no `rawInput`; join it with the earlier `tool_call` update by `toolCallId`. Titles: shell `` `cmd` `` (kind `execute`), `Edit \`path\``/`Write path`/`Delete \`path\`` (kind `edit`, diff content), `Read \`path\``, MCP `<server>: <tool>` with a ```json block (kind `other`), web calls `web_fetch_*`/`web_search_*`. Question prompts reuse the request: their allow options are answers (`__ask_question_skip__` is the reject), never allow them.
  - Native edits never ask in agent mode (any permissions, `approvalMode`, sandbox, outside the workspace too); `ask` and `plan` mode have no edit tool. Shell asks in both modes and runs after approval, but in `ask` mode the model refuses commands that change files.
  - Denying `Read(**)`, `Grep(**)`, and `Glob(**)` makes grep and glob return nothing (a static "no native readers" home is possible, not built). `Read(**)` alone does not.
  - Host: `hostOwnedTools` applies only to `toolAvailabilityEnforcement: "execution-args"`, so with `prepare-execution` no OpenClaw `exec` reaches the model (real run listed 47 tools, `exec: no`), even with `tools.allow` naming it. `tools.deny` hides tools from the model (live). Caps, `disableTools`, and system agents send `toolAvailability.native: []`; the host denies a native tool not in `native` itself and demands `toolAvailabilityEnforced: true` or throws.
  - `openclaw config set tools.deny '[...]' --strict-json` / `config unset` works in the isolated state; unset leaves `"tools": {}`.
- Usage (spike 9, 2026-10-17): ACP gives no usage. The session store `<home>/acp-sessions/<id>/store.db` holds the context total; ACP minus `-p` input is about 1 990 tokens, growth agrees within 1%, output (thinking) is not recoverable. Hooks did not fire here. See `epic-cursor-cli/spike-where-cursor-usage-comes-from-on-acp.md`.
- Tool events (entry 5, 2026-10-17, cursor-agent 2026.10.16 / OpenClaw 2026.10.3):
  - ACP announces a call with a generic title and, for search and MCP calls, empty `rawInput` (`Find`, `grep`, `MCP: tool`); the next update (same ms) has the real title and input. MCP call input: `{providerIdentifier, toolName, args}`; MCP title `<server>: <tool>`. Search titles: ``Find `pat` `` (glob), `grep "pat"`. Completed updates carry `rawOutput`; a rejected shell call still ends `completed`. Call IDs contain a newline. Cursor also sends `session_info_update`, `available_commands_update`, `current_mode_update` (ignored).
  - So the transport lets the adapter wait one update before a call's `toolStart` (`DescribeToolCall` returns `undefined`); without a hook it starts at first sight.
  - Host: our `toolStart`/`toolResult` are display events (`onDisplayToolUseStart`), untracked; the host dedups by call ID itself. The MCP loopback emits no display event, so a proxied call shows only through our start: do not hide it (`--json` `meta.toolSummary` counts calls and tool names; hidden gave 1 call, shown gave 2: `read` + `mcp__openclaw__session_status`). The host strips the `mcp__openclaw__` prefix for display. After an `errorText` result the host drops later tool events, so closing results go before the result/error record.
  - `retryable` never reaches the host (`parseJsonlEvent` returns only `errorText`); it lives in the plugin's own event.
  - ACP message chunks carry no separator between text before and after a tool call (`...sentence.Next text`); not handled.
- Model catalog (entry 6, 2026-10-17, cursor-agent 2026.10.16 / OpenClaw 2026.10.3):
  - ACP `session/new` and `session/load` return `models` (`currentModelId`, `availableModels[{modelId,name}]`, 46 models) and also a `configOptions` model select with the same IDs; the SDK schema does not type `models`. IDs carry brackets (`grok-4.7[context=256k,reasoning_effort=high,fast=true]`, `default[]` is Auto); `name` is the base ID, unique on this account. `session/set_model` and `session/set_config_option` both work; an unknown value fails with `Invalid params` / `Invalid model value`. `cursor-agent --list-models` uses other IDs (`grok-4.7-high-fast`) that ACP rejects: use ACP only.
  - Cursor persists the last model in `CURSOR_CONFIG_DIR/cli-config.json` (`selectedModel`, `model`), so a probe against the shared `~/.cursor` changes the user's default model. Restore with `session/set_model default[]`. In a per-agent home a later `auto` turn would stay on the last model: the adapter switches back to Auto unless the session is already on it (this replaces "auto sends no switch").
  - `session/new` takes about 3 s; a listing is a throwaway ACP session (no prompt) in the temp dir.
  - Host catalog: the provider entry's `catalog.run` (via `providerCatalogEntry`) must return `{provider:{baseUrl, api, models}}`. Without `api` the rows silently never reach `models.list`/`/model` (the host drops the provider). `contextWindow` and `maxTokens` can be omitted. `api: "openai-completions"` is a placeholder: a CLI backend makes no request. `catalog.run` runs only after the plugin is loaded (startup needs `agents.defaults.model.primary = cursor-cli/...`); it is called with `providerIds`, `env`, `signal`, and no refresh flag.
  - `openclaw models list` shows the rows only with a running Gateway (`--port` via `OPENCLAW_GATEWAY_PORT`); `gateway call models.list --params '{"refresh":true}' --port N --json` is the raw view (default view hides unavailable rows; `view: "all"` shows them with `unavailableReason: "missing-auth"`). `models status` stays `[indeterminate]` without a login: the CLI path has no prepared synthetic auth.
  - `pgrep -x openclaw-gateway` fails (name over 15 chars): use `pgrep -f "^openclaw-gateway"`.
  - `cursor-agent status` prints `✓ Logged in as <email>` when logged in.
  - A listing leaves `<config dir>/acp-sessions/<sessionId>` behind; the adapter removes exactly that directory after closing the session. A shared catalog load takes no caller's signal; each caller races its own.
- Session resume (entry 7, 2026-10-18, cursor-agent 2026.10.16 / OpenClaw 2026.10.3):
  - Real Cursor: `session/load` of an id the home lacks gives JSON-RPC `-32602 Invalid params` with `data.message` `Session "<id>" not found` (also for another agent's home); only that session-tied text counts as `session_expired`, a bare `-32602` does not. Two processes can load one chat; each keeps its own view, last writer wins (spec Q4: unsafe), so the core holds one process per chat.
  - The host classifies a backend error from its message text, not our code: `session not found` / `session expired` etc. make `FailoverError reason=session_expired`. It retries a fresh chat only with a history prompt (needs an API-key profile) and clears a failed binding only for `claude-cli`; for `cursor-cli` a lost chat fails every turn until `/reset`.
  - A side question reaches `execute` with `ctx.executionMode: "side-question"`, no `liveSession`, `useResume: false`; `sideQuestionToolMode: "disabled"` is required or the host refuses `/btw` for a backend with native tools. `authProfileId` exists only in `prepareExecution`, not in `execute`.
  - The host's `resumeSession=` log value is a hash, not the native id. Fake agent: `FAKE_CURSOR_STORE`, `FAKE_CURSOR_LOAD_RENAMES`, `[[recall]]`.
- Operations (entry 8, 2026-10-18, cursor-agent 2026.10.16 / OpenClaw 2026.10.3):
  - Real `cursor-agent acp` ignores stdin EOF and stays up after its Gateway is SIGKILLed (orphan); `initialize` carries no `agentInfo`/version; `--version` prints `YYYY.MM.DD-<hash>` in about 0.8 s; the launcher `exec`s node, so the spawned pid is the agent (it also starts a `worker-server` child that is not recorded and can outlive a SIGTERMed parent, seen after a reap, an unload, and a killed listing; a stray one exited by itself within minutes).
  - Unload hook (probed on Gateway SIGTERM): `api.registerService({stop})` and `api.lifecycle.onDispose` run; `registerRuntimeLifecycle({dispose})` does not. The plugin registers the first two (`closeAll` is idempotent). Gateway SIGTERM waits for `stop`: the fake and real processes are gone when it exits.
  - Host: the queue key with `liveSession` is `<backend>:owner:<hash(account, agent, authProfile, sessionId, sessionKey)>`, so two calls to one session run one after the other (live, fake log) and two agents run at once; `MAX_LIVE_SESSIONS = 16` is global (evicts an idle handle, else `rate_limit`); a watchdog wraps plugin `execute` (no-output and overall timers, aborts `ctx.abortSignal`); the host deletes `config.clearEnv` keys before `ctx.env`; `runtimeArtifact` supports only a `bundled-package-tree` identity, which Cursor's bash launcher beside `@anysphere/agent-cli-runtime` (no version) cannot give.
  - Core: `ProcessPool` per backend (turn semaphore, process registry with LRU idle eviction, `closeAll`, version memo) in `src/core/pool.ts`; pid locks `<home>/pids/<pid>.json` and reaping in `src/core/pid-locks.ts` (a process is killed only if pid and `ps` start time match and the owner pid and start time no longer exist; a zombie counts as gone). A turn slot is taken before anything else; `createEntry` counts the process in the pool until `handle.close`. The model listing's throwaway process is not locked or pooled.
  - Executing TypeScript directly with `node` needs `--experimental-transform-types` (parameter properties).
  - Review fixes (1.8): a dead idle process is evictable and frees its slot on exit; `pool.add` is async and waits (3 s) for the evicted process to exit, so the cap holds and a chat is free before `session/load`; `handle.close` aborts an in-flight open; the version check runs once for concurrent turns (`checkVersionOnce`); `ps` runs with `TZ=UTC`; an unavailable `ps` is never memoized; the host rejects out-of-range caps (schema min/max) before the plugin loads, only `maxProcesses < maxConcurrentTurns` reaches the plugin and resets just the caps; a side question takes a turn slot.

- Usage (found after ticket 1.9): exact per-turn tokens come from Cursor's server ledger. `POST https://api2.cursor.sh/auth/exchange_user_api_key` (Bearer API key, body `{}`) gives `accessToken`; `POST /aiserver.v1.DashboardService/GetFilteredUsageEvents` (Connect-Protocol-Version: 1, body `{"page":1,"pageSize":20}`) lists events newest first; match `conversationId` = ACP sessionId and the turn's timestamp; `tokenUsage{inputTokens(excl. cache),outputTokens,cacheReadTokens,cacheWriteTokens}`, a missing count is 0. One event per ACP turn, visible ~1 s after `session/prompt` returns; matched `-p` to the token. Undocumented: degrade to no usage on any failure. ACP never fires hooks. Details: the spike's Addendum.
- Chat continuity (entry 11, 2026-10-18, OpenClaw 2026.10.3 / cursor-agent 2026.10.16):
  - Host history boundary: a switch from an API model to `cursor-cli` gives `historyPrompt=none` and the log line `cli session history refused across auth boundary: reason=auth-unknown`, with or without a `cursor-cli` `api_key` profile. The plugin therefore puts a note (`CONTINUITY_NOTE`, `src/core/execute.ts`) before the first prompt of a fresh agent chat that has the proxy; Cursor then calls `sessions_history` (shown as `mcp__openclaw__sessions_history` in `toolSummary.tools`) and answers correctly. `sessions_history` runs through the Gateway: it fails under `--local`. A cursor, API, cursor chat also read the API-turn fact. An API turn after cursor turns sees their user and assistant text in its request.
  - Profile: `printf '%s\n' "$KEY" | openclaw models auth paste-api-key --provider cursor-cli` (non-interactive; profile `cursor-cli:manual`); remove with `models auth logout cursor-cli:manual --yes`. The key is not given to `cursor-agent`.
  - With the profile and `reseedFromRawTranscriptWhenUncompacted`, a lost `cursor-cli` chat gets `historyPrompt=present`, but the host's fresh retry cannot run. The host mints one MCP loopback grant per run. The fresh retry reuses the same prepared backend, so it gets no new grant. In the first attempt the plugin's `live.register` stores the run's own grant token; `session/load` fails, the plugin closes its handle, and `live.remove` revokes that token; the retry's register/activate then throws `CLI MCP client grant is no longer valid`. Skipping the close does not help (the host closes the record itself on a fresh retry). Through a Gateway the retry is blocked earlier: the host's session-entry copy has a stale `activeWriterRunId`, so it cannot clear the failed binding. So a lost chat is host-blocked in both paths on OpenClaw 2026.10.3. The only plugin-side fix would be a probe that the native chat exists before `live.register` (fragile, changes resume behavior); deferred. Recheck on a newer OpenClaw.
  - Mock API model for live tests: `test/fixtures/mock-openai-api.mjs`, registered with `config set models.providers.mockapi '<json>' --strict-json` (`api: "openai-completions"`, `apiKey`, `models:[{id:"echo"}]`), used as `--model mockapi/echo`. `openclaw agent --verbose` takes a value (`on|off`). The Gateway log (`/tmp/openclaw/openclaw-<date>.log`, JSON lines) holds `cli exec: ... historyPrompt=` and is written a moment after the reply; read it by byte offset.
  - Debugging a host module: copy it aside, add a `console.error` guarded by an env var, restore it after (done for `cli-session-store`, restored).
- Usage (entry 10, 2026-10-18, cursor-agent 2026.10.16 / OpenClaw 2026.10.3): built as the optional `CliAdapter.readUsage` port; `src/core/usage.ts` `readTurnUsage` calls it once per `result` turn without an ACP `usage`, after the closing tool records; the Cursor reader is `src/adapters/cursor/usage.ts` (ledger, see above). Probed: the exchange gives `{accessToken, refreshToken}`, the token is a JWT with `exp` (TTL 3600 s); the ledger answer is `{totalUsageEventsCount, usageEventsDisplay[]}`, `timestamp` a ms string, `tokenUsage` may omit `cacheWriteTokens`; a bad token gets 401. The transcript is SQLite `<state>/agents/<agent>/agent/openclaw-agent.sqlite`, table `transcript_events(session_id = OpenClaw session id, seq, event_json)`; an assistant entry is `event_json.message` with `provider: "cursor-cli"` and `usage{input,output,cacheRead,cacheWrite,totalTokens}`; read it with `node:sqlite` read-only. Live (`test/live/usage.live.test.ts`): the entry equals the ledger's event field by field, and a second turn of the same chat gets only its own event (the ACP session id is the same across turns). `openclaw agent --json` prints the usage under `meta`. Node 24 `fetch` ignores `HTTPS_PROXY` unless the process starts with `NODE_USE_ENV_PROXY=1` (`dev-openclaw.sh` and `npm run test:live` set it; a bare `npx vitest run test/live/...` needs it by hand). `OPENCLAW_ALL_CLI_CURSOR_USAGE_URL` moves the ledger calls (tests) and is in `CURSOR_CLEAR_ENV`. Login-only accounts get no usage (open question: reading Cursor's stored login would fix it; not done).
